# frontend — Web Music Player SPA

Angular 22, **zoneless**, standalone components. Server state via **TanStack
Query** over a **generated HeyApi** fetch client (ADR-0006). Component
communication follows a presentational/container split with a capped
event-forwarding depth (ADR-0007) — see
`../Documentation/adr/0007-frontend-component-communication.typ` and
`../Documentation/arc42/sections/05-building-block-view.typ` for the full
picture. Unit tests run on Vitest (Angular 22 default); E2E on Playwright;
accessibility on pa11y-ci.

## Layout

```
src/app/
  api/            generated — do NOT edit (pnpm generate:api). See api/README.md
  api-runtime-config.ts   HeyApi client defaults (baseUrl /api, credentials include)
  auth/           AuthService (BFF redirects), auth-redirect (401 → login), UserMenuComponent
  core/           app-wide singletons (interceptors, guards) — currently empty
  shared/
    song-asset-urls.ts   cover/audio URL builders
    songs/                SongListPanelComponent (smart) + presentational row/menu/skeleton
  features/
    songs/          SongsPageComponent (route), SongUploadComponent
    playlists/       PlaylistsPageComponent, PlaylistDetailComponent (routes), ui/*
    player/          PlayerService (signal store), PlayerComponent, PlayerDrawerComponent, ui/*
  app.config.ts   providers: router, TanStack Query, i18n, Optimus UI theme
e2e/              Playwright specs (run against the full Compose stack)
scripts/          helper scripts for e2e/a11y tooling (not shipped in the build)
```

## Scripts

| Command | Purpose |
| --- | --- |
| `pnpm start` | `ng serve` — proxies `/api` → `http://localhost:3000` (`proxy.conf.json`) |
| `pnpm build` | production build → `dist/` |
| `pnpm test` | unit tests (Vitest via `ng test`) |
| `pnpm typecheck` | `tsc --noEmit` |
| `pnpm generate:api` | regenerate `src/app/api/` from `../backend/openapi.json` (commit it) |
| `pnpm e2e` | Playwright against `https://localhost:8443` — bring up Compose first (`docker compose up -d` at the repo root) |
| `pnpm a11y` | pa11y-ci (WCAG2AA) against the same live Compose stack |

## API client workflow

`../backend/openapi.json` (committed, generated by `@nestjs/swagger` from the
backend's controllers and DTO classes) is the single source of truth. After it
changes: `pnpm generate:api`, commit the `src/app/api/` diff. CI regenerates
and `git diff --exit-code`s it.

```ts
import { injectQuery } from '@tanstack/angular-query-experimental';
import { songsControllerListOptions } from './api/@tanstack/angular-query-experimental.gen';

readonly songs = injectQuery(() => songsControllerListOptions());
```

## E2E and accessibility testing

Both `pnpm e2e` and `pnpm a11y` run against the real Compose stack (nginx +
NestJS API + Postgres + Keycloak) — bring it up first:

```bash
docker compose up -d --build
```

- `pnpm e2e` — an `auth.setup.ts` project logs in once as the seeded `dev`
  user (`keycloak/import/wmp-realm.json`, password `dev`) through the real
  Keycloak-hosted login form and saves the session as Playwright storage
  state; the `chromium` project's specs (`e2e/*.spec.ts`) reuse it. Specs
  share one backend and one user with no per-test data isolation, so they run
  `workers: 1` and each spec deletes what it created.
- `pnpm a11y` — `scripts/a11y-session.mjs` logs in over the REST API and
  seeds one song + one playlist so the scan sees populated markup, then
  `.pa11yci.cjs` runs pa11y-ci against `/songs`, `/playlists` and that
  playlist's detail route, each authenticating fresh through pa11y's own
  action scripting (see the comment at the top of `.pa11yci.cjs` for why a
  plain cookie header doesn't work here).
